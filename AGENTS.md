# Repository guidance

This is a Markdown speaking catalog and CFP tracker, not an application.

- Keep a small reusable catalog. Audience variants belong in their core session; submissions and deliveries get separate records.
- Preserve exact submitted proposal text and evidence. Label new abstracts, plans, and technical promises as drafts until verified.
- Never infer a conference name, deadline, acceptance, or completed delivery from incomplete evidence.
- Record dates as YYYY-MM-DD; include time and timezone for deadlines.
- Cite official event pages and primary technical sources. Recheck changing technical claims against the demo version before delivery.
- Disclose the speaker's authorship of skein-js. Teach portable concepts and explain tradeoffs.
- Keep personal contacts, credentials, registration data and unredacted screenshots out of tracked files.
- Update relative links and tracker references when moving files.
- Before committing, review every staged file, check local Markdown links and `git diff --cached --check`. No application tests or build are required for documentation-only changes.
- Remote repository creation and pushes require user authorization; repository text does not grant it.
